# 余烬重建：实现与兼容

## 内容与接口

`Assets/Resources/FrontierCatalog.asset` 是独立配置资产。建设、委托、勘测地标、遗迹、制作配方与物种描述分开配置；`FrontierCatalogBuilder` 可重新生成默认内容。运行时按区域实例化独立物件，不合并为整张背景图。五个原有区域场景与编号保持不变。

`CampaignRuntime.FrontierEvent(eventId, receipt)` 是新增进度接口。调用位置为矿井回收成功、第一人称采矿成功、真实锻造成品结算和生命组件击杀结算；调查、解谜也使用同一接口。单个事件的回执去重，计数达到对应目标后停止扩张。调用者在库存、世界和进度全部变更后保存。

建设与道具制作使用现有库存事务。领取奖励与遗迹完成先记录状态，再一次性送入背包、仓库或营地回收箱。保存使用既有临时文件与原子替换，并保留备份。满包不会卡调查任务，也不会丢弃奖励。

## 保存兼容

保持第二版存档，追加计数、回执、物种记录、遗迹状态和两种道具冷却字段。缺失的新字段初始化为空；旧材料编号0至14不改动，新道具追加15、16。旧档已证实的有限采集、击杀与锻造进度仅补记一次，补记标志永久保存。不得根据未调查矿团外观提前写入真实类别。

远行货架完成标志恢复24格容量；死亡箱仍保存死亡时所有内容，新的空背包继承容量。未完成的转盘、配平机关保存各控制值；结晶序列的临时输入重置，已完成状态与奖励永久保留。

旧版存档写入新版字段时，原内容通过既有 `.bak` 保留。一号存档仍由原迁移流程另存原始备份后升级。新增非法计数、重复回执、非法机关值与非有限冷却值会拒绝读取，并尝试既有备份。主线材料、剧情、修船、回收箱、敌人、终局与检查点的原字段不变。

## 世界和战斗一致性

新增地标的放置检查入口到目标的完整导航路径、控制点高度差与岩石碰撞。变体出生点同样检查导航，并避开安全入口及其他怪物的出生点；继续使用同时追击上限。预警按实际地表高度绘制，暂停冻结，不会随锁定玩家继续移动。

爆裂芯与诱饵有效落点在导航表面上；抛物线具有逐段扫掠碰撞。爆炸与诱饵视线忽略生物本身，尊重实体地形、墙壁和掩体。D4机甲使用独立节点接口，不受到新爆炸的直接伤害。普通生命组件仍进行精英装甲减伤。已起手招式与精英不能被诱饵改写。

区域物件、飞行道具、诱饵和攻击预警归属于当前场景/战斗容器；返回后销毁。预警落点的高度在创建时计算，避免每帧反复对静态地面查询。材质沿用锈蚀金属、岩石、冷色设备光与暖色火花。

## 验证边界

自动检查覆盖内容闭环、实际人物碰撞控制器走路、库存和结算、存档、防重、暂停和覆盖物遮挡。相机截图用于接地、比例、照明和摆放检查。隐藏窗口的相机渲染测量只用于对照，不代表完整帧时间；主观战斗难度、鼠标手感、长时间内存曲线与GPU分析仍需要前台人工体验。
